# 先分离，再串行化共享状态

当并发参与者可能写入同一个文件、分支、键或对象时，先问他们是否需要同一个共享对象，还是在发布各自独立的事实。默认给每个参与者自己的文件、键、分支或状态目录，只在读取状态的地方合并。两个 worker 各自往同一个 `state.json` 里写自己的字段，仍然是共享变更。

只有当单一共享写入目标确实是真正的不变式时，才从结构上串行化访问（锁文件、单一写入方、顺序阶段、比较并交换）。指令不是并发控制，而“我们需要一把锁”是需要先核查的气味。
