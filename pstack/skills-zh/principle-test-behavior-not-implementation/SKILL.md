# 测试行为，而非实现

测试是对代码使用者能通过接口观察到什么的主张：返回值、错误、可回读的状态，以及对系统外部的影响。私有辅助函数、内部调用顺序和中间数据都属于实现。

用两个想象中的改动来检验每个测试：

- **破坏行为**（一个错误的值、一次被跳过或被重复执行的效果）。如果测试仍然通过，它什么也没证明。常见原因是断言过于宽松、期望值由被测代码自己计算得出，以及对测试自己构造的数据做断言。
- **改动内部实现**，同时保留每一个可观察结果。如果测试失败，说明它被钉在了实现上。

保留能捕获第一个改动、并在第二个改动下存活的测试。其余的重写或删除。用具体输入通过公开接口驱动代码，并从需求推导期望值。外部服务收到什么是行为。调用内部辅助函数不是。把“这永远不会发生”与一个它确实会发生的用例配对。断言调用方据以分支的错误类型，而不是错误消息。
