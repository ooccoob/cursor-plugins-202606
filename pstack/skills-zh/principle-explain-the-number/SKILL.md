# 解释这个数字

- **先写下决策，再运行。** 说出哪个结果会改变这个决策，以及噪声底线。当运行间的离散度大于效应本身时就停下来。
- **问“为什么不是翻倍？”** 从运行期间采集的 profile 或计数器里，指出限制该结果的资源或代码路径。读代码猜出来的不算限制因素。
- **列出这个数字还可能测到了什么**（错误、被跳过或被缓存的工作、从未运行的代码、未被调优的一侧、噪声、小到无关紧要的一块），并用证据逐一排除。
- **把运行次数、离散度和限制因素与数字一起保留。**

对性能数字，运行 [benchmark-checklist](../benchmark-checklist/SKILL.md) 技能。对评测结果，问每一次运行是否都做了任务、差距在多次试验和多个模型上是否成立、该场景是否重要。
