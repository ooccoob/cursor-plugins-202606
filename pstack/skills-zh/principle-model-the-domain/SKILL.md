# 建模领域

把领域编码进一个数据结构，而不是把它散落在条件分支里。正确的结构能让非法状态无法表达，并删除分支。

需要状态机而不是散落的布尔值或阶段判断，需要带类型的模型而不是松散的参数，需要 map、注册表或可辨识联合而不是散落在多个文件里的分支，需要 reducer 而不是临时拼凑的变更，需要索引、队列或规范化集合时就按访问模式来用。

不要强求。当形状清晰、局部、且不太可能增长时，保留平淡的代码；也要警惕那种只增加间接层、却不消除分支或非法状态的抽象。

你跳过了这条的迹象：某个功能又多出一条 if/else 分支，或多出第二个必须与第一个保持同步的布尔值。
