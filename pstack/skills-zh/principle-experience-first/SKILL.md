# 体验优先

当实现便利与用户愉悦冲突时，选择愉悦。

- 每个功能、控件和选项都必须被证明有存在价值
- 少交付、交付得更好（三个打磨到位的功能胜过十个粗糙的功能）
- 先做原型再定稿（设计决策在一次性 HTML 里比在生产代码里更便宜）
- 把细节做对（过渡、对齐、间距、反馈、错误状态）
- 收紧核心循环（每个功能都应服务于中心工作流，否则就让开）

用户就是消费这项工作的人。对 UI 来说就是终端用户。对库或内部 API 来说，就是 import 它的同事。下一位维护这段代码的工程师也是用户。用同样的方式权衡他们的体验，并从他们的视角解释影响。

基础应当服务于体验。基础性思考管的是工作的*顺序*。这条原则管的是*目标*。
