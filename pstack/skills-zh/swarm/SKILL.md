# 集群

## 开始

在启动任何东西之前，打开一个待办清单，每个阶段一条。

1. 框定
2. 扇出
3. 汇总
4. 报告

## 阶段 A：框定

1. 陈述完成谓词，以及集群必须返回的产物或报告。
2. 选择形态。分片划分、让 N 个工作者按相同简报竞速，或两者混合。对于竞速或混合形态，在生成之前声明 `first pass`、`rank all` 或 `best-of`。
3. 从 `~/.cursor/rules/pstack-models.mdc` 中的 `swarm workers` 行挑选工作者模型。如果规则或该行缺失，使用 `claude-opus-5-5-high-fast`。对于 `auto` 或 `inherit-parent`，省略 `model`，让工作者跑在父模型上。如果 Task 工具拒绝某个 slug，用默认值并说明。如果它连默认值也拒绝，用其错误信息中同系列最接近的有效 slug。对于模型竞速，提前给每一路命名所用模型。按 **poteto-mode** 技能的 Subagents 章节，为每个子代理挑选适合该任务的推理等级。
4. 当工作者会写文件时，给每个工作者自己的可写输出。当工作者验证或测量提交时，每份简报点名确切的 SHA。测量简报还要点名方法（样本数、一个样本是什么、顺序）。工作者在结果中记录两者。

## 阶段 B：扇出

在一条消息里生成全部 N 个工作者，使用 `subagent_type: generalPurpose`、`environment: "cloud"`、`run_in_background: true`，以及第 3 步的模型，对 `auto` 或 `inherit-parent` 则留空。仅当工作者需要访问用户计算机上的东西时才用 `environment: "local"`。

当工作者必须从非默认的已推送分支开始时，传入 `cloud_base_branch`。

每份简报独立成立。包含目标、范围、确切的切片或竞速分路、如何验证、以及报告什么。报告使用 `PASS`、`ISSUES` 或 `BLOCKED`，并附证据。能证明缺陷的工作者报告 `ISSUES`，并列出它能证明的每个问题，而不只是第一个。

如果某个工作者掉队，用 N-1 继续并注明。

## 阶段 C：汇总

读取终态结果。丢弃未记录其简报所点名 SHA 与方法的结果，并重生成该工作者一次。第二次仍未命中，记录一个缺口。缺口不算通过。对于覆盖任务，每个必需切片都需要有结果。对于竞速，应用事先声明的选择规则。使用 first pass、rank all 或 best-of。不要粘贴工作者的原始转储。

## 阶段 D：报告

返回一份合并的对话内报告，包含结果表格、问题一句话摘要、缺口或掉队情况，以及使用时的竞速规则。
