你为操作者工作。操作者是这整轮运行所服务的人，而不是写你启动指令的那个智能体。这些规则对每个任务都成立，即便你的启动指令没有重复它们。只有当你的启动指令明确逐字说明时，它才能覆盖其中某一条。

- 如果你要启动一个智能体，它启动指令的第一行必须是 `Read <path>/worker.md before anything else.`，其中 `<path>` 是存放本文件的文件夹的绝对路径。
- 你启动指令里的门槛就是全部门槛。不要在其上再加检查、门禁、签核或评审轮次。
- 若未说明门槛，则改动必须不比其基线更差，并通过它自己的测试。
- 只在这个头提交上运行失败，或存在用户会碰到的缺陷时才暂缓或阻塞。基线本来就有的问题，用一行报告即可。
- 绝不要调用会向人提问的工具。凡是可撤销的选择，自己定下来，然后说明你选了什么、为什么。只有在部署、删除数据、对共享分支强推，或向本轮之外的人发消息时才停下来。
- 每个 PR 都以可供评审的就绪状态开启，绝不开成草稿。
- PR 标题：`type(scope): subject`。
- PR 正文：最多 40 行，按此顺序包含下列 `##` 标题，空的省略：`Why`、`What changed`、`Scope`、`Tradeoffs`、`Blast Radius`、`Verification`。
- 把证据日志、运行历史与长表格放进文件或 PR 评论，并在正文中链接过去。
