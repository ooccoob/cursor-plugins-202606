### 重构（Refactoring）

**契约由你负责。结构变，行为不变。** 这与功能开发不同（后者增加行为），也与缺陷修复不同（后者纠正行为）。

如果清理过程中暴露出缺失的功能或真实的缺陷，把它拆出去，先针对钉住的契约交付结构性改动。允许重新设计，但要明说并路由到功能开发。大型或横切的结构性工作属于 **figure-it-out** Skill。本手册处理的是聚焦到中等规模的改动。

1. 先钉住行为契约。追查受影响的子系统以了解契约，然后在任何结构挪动之前，写出特征测试、快照或等价性夹具，把当前行为捕捉下来。如果该区域没有覆盖，就在碰结构之前先写这个钉子。类型检查与 lint 不是钉子。
2. 按 **principle-model-the-domain** 指出代码缺失的结构。当形状已经清晰且局部时，就让平淡的代码留着。重塑必须删掉分支或非法状态，而不是增加间接层。
3. 指出目标形状。说明如果今天从零构建，模块布局、类型与调用图应当是什么样（**principle-foundational-thinking**、**principle-redesign-from-first-principles**）。如果目标跨越函数边界，在动手前先跑 **architect** Skill 定形态。
4. 先减后加。在引入新形状之前，删除死代码、合并只有一个调用者的包装、去掉冗余校验、清除孤儿引用（**principle-subtract-before-you-add**）。能达到目标形状的最小改动才交付（**principle-laziness-protocol**）。那种“可能有用”的投机性清理会被回退。
5. 以小步、保持行为的方式挪动，每一步都让钉子保持通过。对 API 重塑，在同一次推进里迁移所有调用方并删掉旧 API（**principle-migrate-callers-then-delete-legacy-apis**）。不加兼容垫片，不留新旧并行的路径。每次重命名都对照实际文件抽查。重命名会静默漏掉字符串、文字与反向引用里的用法。把机械性编辑委派给子代理，使用你配置的重构模型（默认 `claude-opus-5-5-xhigh-fast`），给出具体范围（文件路径、要挪动的名字、要保持的行为）。按 Subagents 章节所述，为每个子代理按任务选择推理档位。
6. 在真实产物上证明行为未变，而不是“它能编译”（**principle-prove-it-works**）。对更大的重塑，跑一次等价性检查：一个对比新旧输出的脚本、一份对新代码重放的录制基线，或经由相关控制 Skill 在匹配界面上做一次冒烟运行。
7. 确认这处改动值得保留。成功度量是读者负担下降（**principle-minimize-reader-load**）。如果 diff 没有在任何地方降低读者负担，就回退它。
8. 变基成小而有序的提交。先一个减法提交，再是重塑，然后任何后续清理。用 **sequence-verifiable-units** 原则 Skill 塑形，使每个保持行为的切片在下一切片之前保持通过。运行**开启 PR**。

**回复：** 改动的结构，你用来钉住它的钉子，等价性证明，读者负担的差值，交付了什么、回退了什么。不引入新行为。
