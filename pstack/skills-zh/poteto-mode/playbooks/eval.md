### 评估

**你负责实验设计。规划、盲化、运行、综合。**

**盲化的不可妥协项：**

- 候选方看到的任何目录、文件或提示中，都不得出现 `eval`、`test`、`judge`、`experiment`、`rubric`、`score`、`compare`、`benchmark`、`candidate` 或 `arena`。
- 给候选方的提示要像一个自然的用户请求。陈述目标，不要暴露元信息。
- 不要有引导链条的暗示。不要让候选方列出它用了哪些 skill、原则或文件。笼统地要一份设计说明，并从代码形态而非自我陈述来评判链条遵循情况。
- 清理目录名与 slug 名。用用户可能自己取的、像项目一样的名字。
- 不要告诉候选方还有其他候选存在。
- 评判者可以知道自己在评判，但只看得到以清理后标签呈现的输出，永远看不到模型名。
- 比较两个变体时：让同一个评判者在同一尺度上一次性给两组打分，且不知道每组来自哪个变体。

**步骤：**

1. **框定。** 说明被测的是哪个变体，以及什么行为算成功。只为评判者写评分标准（3-6 条具体准则）。不要给候选方看。
2. **搭建清理过的环境。** 每个候选方一个工作目录，变体已就位。把自然任务本该有的上下文都放进去：项目骨架、候选方自然会读的那些 skill。
3. **写一条自然的提示。** 就是用户会打出来的话。不泄露正在衡量什么。
4. **派生 N 个并行候选方**，按 **arena** skill 的 Phase B 在不同模型上进行。每个都在自己清理过的目录里工作。给每个人的提示相同。按 Subagents 一节，为每项工作挑选子代理的推理等级。只负责派发、轮询或打包结果的智能体用 `claude-opus-5-5-medium-fast`。
5. **派生一名盲评判者**，按 **arena** skill 的 Phase C 在另一个模型家族上进行。评判者只看以清理后标签呈现的输出和评分标准，永远看不到模型名。
6. **从轨迹而不是自我陈述来核实链条。** 读每个候选方在活动工作区 `agent-transcripts/` 目录下的本地轨迹（系统提示会给出该路径）。不要跨 `~/.cursor/projects/*/` 做 glob，那会跨越工作区边界，读到无关项目的私密对话。看每个候选方实际打开了哪些文件。从它真正读过的文件加上代码形态来评判链条遵循情况，绝不采信候选方自己的说法。
7. **自己从头到尾读完每个候选方的输出。** 与评判者的裁决对照。出现分歧意味着某个模型有偏差，或评分标准有歧义。据此综合。

**回复：** 被测变体、评分标准、每个候选方的记录、评判者的裁决、你的综合，以及是否推广该变体的建议。
