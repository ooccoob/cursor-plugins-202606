# 结果导向执行

为预期的、可验证的最终状态优化，而不是为了保留平滑的中间态。

**为什么：** 让每个中间步骤都完全稳定，往往会产生临时兼容代码，最终变成长期债务。向目标架构收敛，并在明确的验证边界上证明正确性。

**核心规则：**
- 最终状态的完整性优先于过渡期的稳定性
- 当中间态破损是有计划的、有范围界定的且可回退时，可以接受

**护栏：**
- 用于带明确阶段边界的计划性重写和迁移
- 声明哪里可以接受临时破损
- 迁移期间，对正在改动的区域保留高信号检查
- 计划完成时要求完整的静态与运行时验证
