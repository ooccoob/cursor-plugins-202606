# 构建杠杆

当工作不平凡时，构建做这件事的工具（codemod、脚本、生成器或可重跑的检查），而不是手工完成。判断标准是平凡与否，不是重复与否。只有两三处显而易见的编辑才可以跳过工具。

- 先手工做完第一个单元，然后构建工具，并在那个单元上重跑以证明它。让它可安全重跑。
- 确定性工具胜过扇出。真要扇出时，把配方、验证契约和围栏写成一份 Skill，交给被委派者阅读，且他们不能编辑。
- 应用这条原则会产生一个文件。diff 里没有脚本、codemod、生成器或委派 Skill，就说明你没应用它。当工作活得比本次会话更久时，把它提交。
- 构建能完成或证明这件事的最小脚本，绝不要框架。
