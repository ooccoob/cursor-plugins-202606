# 回溯

**开始或恢复工作之前，重建用户近期的工作上下文，并交回一份紧凑的胶囊摘要，说明当前进展和下一步。**

保持紧凑且切题。只读范围内线索所需的内容，然后停下。

你的上下文存在于两份记录中。你自己的对话历史保存你做过什么、决定了什么。共享记录保存同一份代码周围以其他名义发生的一切：用户反复报告的症状、已发布又被回滚的修复、生产环境仍在触发的错误。第二份记录存在于源码管理、issue 跟踪器、聊天与 issue 频道、长篇文档和错误跟踪中。一个有长期 bug 尾巴的功能，其故事大多在那里，所以不要仅凭对话记录重建它。

对话记录位于 `~/.cursor/projects/<slug>/agent-transcripts/<uuid>/<uuid>.jsonl`，其中 `<slug>` 是 workspace 路径去掉开头斜杠、把每个 “/” 换成 “-”（所以 `/Users/you/proj` 变成 `Users-you-proj`）。每一行是一条聊天消息。

1. 先分类，再路由。要恢复某一次具体的既往对话是 `session-pickup` 手册，不是这里。把习惯变成持久 skill 是 `automate-me`。工作的人类可读摘要又是另一项任务。回溯是在你行动前跨近期对话加载工作上下文。若用户已给出完整的状态胶囊（路径、分支、改动），就用它并跳过挖掘。
2. 搜索前先锁定范围。钉住时间窗口（“近期”是真实范围，默认最近 7 天）、话题（若有指定）和 workspace（默认为当前活动者。未经要求绝不读其他项目的对话记录）。把范围复述回去。绝不悄悄把“全部”变成“最近 N”。
3. 在对话历史上分发。用快速便宜的模型并行启动子代理，各自负责语料的一个切片。告诉每个子代理按真实修改时间（`ls -t`）排序候选，绝不按 UUID 名称；先 grep 话题，然后只读匹配的对话且只读其相关区域；并跳过当前对话及明显噪音（子代理、eval 和测试对话）。每个都返回同一 schema，每段对话一块：话题、用户目标、决策、未结线索、挣扎与纠正，以及产物（PR、ticket、分支），各自标注对话 UUID。只有一两个对话时，跳过分发直接搜索。原始对话记录留在子代理中。主线程只拿到它们的发现。按 **poteto-mode** skill 的 Subagents 一节，为每个子代理的推理层级按任务选择。
4. 只要话题涉及某个功能、文件、子系统、领域或 bug，就扫一遍共享记录。这是默认做法，不是需要判断的选择，“我在 X 上的工作”也不豁免。每个来源启动一个调查子代理，用 agent 模式（readonly 会剥离 MCP 访问），各问“当前状态如何、试过什么但没站住、用户还在报告什么”。与对话历史挖掘并行运行。空结果也是发现。不可用的 MCP 就跳过并说明。把回来的内容折进简报。仅对没有指名目标的纯活动回溯（“我这周做了什么”）跳过此步，此时你自己的历史和实时状态就是全部答案。
5. 对照实时状态验证。取挖掘和扫查浮现的 PR、分支和 ticket，用 `git` 和 `gh` 核对。当答案取决于某个智能体实际做了什么（运行的工具有哪些、读了哪些文件、撞到哪些错误），读完整对话记录，而不只是裁剪过的本地副本。
6. 按下述契约写简报。按线索分组。紧扣指定话题。

## 输出契约

先给胶囊，然后线索状态，然后问题，然后下一步。更深的细节放在下面或砍掉。

- **胶囊。** 最多 5 条项目符号。这项工作是什么，整体进展如何。
- **线索。** 各一行，前缀恰好一个状态标签：`[merged #N]`、`[open PR #N]`、`[in flight <branch>]`、`[verified, uncommitted]`、`[reverted #N]` 或 `[planned, not started]`。没有标签的线索就是尚未完成，所以给它打标签。
- **问题。** 最多 5 个，反复出现的那些。包含用户反复报告的症状，以及已发布又被回滚的任何修复，使下一次尝试从上次失败处开始。
- **下一步。** 单个最有用的下一步行动，要具体。

相邻的功能或 ticket 不列入，除非它阻碍这一项。当胶囊和线索行超出一屏时，先砍细节再砍线索。简报通过 **unslop** skill 撰写，对话发现按 UUID 引用，共享记录发现按其来源引用（PR #、ticket ID、聊天永久链接、错误跟踪 issue），并在任何公开输出前脱敏私人上下文。

**回复：** 简报，符合上述契约。
